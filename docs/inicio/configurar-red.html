6. Configurar red y config.h

La ESP32 y el computador con Docker deben estar en la misma red, y la ESP32 debe conocer la IP del computador. Aquí defines ambas cosas en config.h.

Elegir la red

La ESP32 solo usa WiFi de 2.4 GHz. Tienes dos opciones:

OpciónVentajaDesventaja
A. Hotspot del computador (recomendado en clase)Funciona igual en cualquier lugar; la IP del PC es fija y conocida.El PC necesita otra conexión (cable o WiFi) para tener Internet en el hotspot.
B. Router existente (casa/laboratorio)No hay que configurar nada en el PC.La IP del PC puede cambiar; algunas redes institucionales aíslan a los clientes entre sí.
Redes universitarias / con portal cautivo

Redes con página de inicio de sesión o con aislamiento de clientes impiden que la ESP32 vea al computador. En ese caso usa la opción A.

Opción A: crear el hotspot

  1. Abre la configuración. Configuración → Red e Internet → Zona con cobertura inalámbrica móvil.
  2. Edita las propiedades. Define nombre (SSID) y contraseña (mínimo 8 caracteres).
  3. Banda: 2.4 GHz. Si aparece la opción Banda de red, elige 2.4 GHz (o “Cualquiera disponible” si no existe 2.4; la ESP32 no verá la red si queda en 5 GHz).
  4. Actívalo. Windows asigna al PC la IP 192.168.137.1 en esa red.

Con NetworkManager (Ubuntu y la mayoría de escritorios):

# Reemplaza wlan0 por tu interfaz (ver: nmcli device)
nmcli device wifi hotspot ifname wlan0 ssid MiHotspot password "clave-segura-123" band bg

band bg fuerza 2.4 GHz. NetworkManager suele asignar al PC la IP 10.42.0.1. También puedes hacerlo gráficamente: Configuración → Wi-Fi → ⋮ → Activar punto de acceso.

Averiguar la IP del computador

Es la IP del PC en la red a la que se conectará la ESP32, no la de otra interfaz.

ipconfig
  • Con hotspot: busca Adaptador de LAN inalámbrica Conexión de área local* N → IPv4: 192.168.137.1.
  • Con router: busca Adaptador de LAN inalámbrica Wi-Fi → p. ej. 192.168.1.50.

Ignora los adaptadores vEthernet (WSL) y Docker: son redes virtuales internas.

ip -4 addr show | grep inet
  • Con hotspot: la interfaz WiFi mostrará 10.42.0.1/24.
  • Con router: algo como 192.168.1.50/24 en wlan0/wlp2s0.

Ignora docker0 (172.17.0.1) y lo (127.0.0.1).

No uses localhost en la ESP32

localhost / 127.0.0.1 significa “yo mismo”. Para la ESP32 eso es la propia ESP32, no tu computador.

Abrir el puerto 8000 en el firewall

Por defecto el firewall puede bloquear conexiones entrantes desde otros dispositivos.

PowerShell como administrador:

New-NetFirewallRule -DisplayName "Backend ESP32 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Private,Public
New-NetFirewallRule -DisplayName "Frontend 3000" -Direction Inbound -Protocol TCP -LocalPort 3000 -Action Allow -Profile Private,Public

Para eliminarlas después: Remove-NetFirewallRule -DisplayName "Backend ESP32 8000".

Ubuntu trae ufw desactivado por defecto. Si lo tienes activo:

sudo ufw allow 8000/tcp
sudo ufw allow 3000/tcp

Nota: Docker publica los puertos insertando sus propias reglas de iptables, que normalmente tienen prioridad sobre ufw.

Comprobar desde otro dispositivo

Conecta tu celular a la misma red y abre http://<IP-del-PC>:8000/mensaje. Si ves el JSON, la ESP32 también podrá llegar.

Crear config.h

El sketch lee la configuración de esp32/esp32_mensaje/config.h. Ese archivo no está en el repositorio (está en .gitignore) para no publicar contraseñas; se crea a partir de la plantilla:

Copy-Item esp32\esp32_mensaje\config.example.h esp32\esp32_mensaje\config.h
notepad esp32\esp32_mensaje\config.h
cp esp32/esp32_mensaje/config.example.h esp32/esp32_mensaje/config.h
nano esp32/esp32_mensaje/config.h

Edita los cuatro valores:

#pragma once

// Red WiFi a la que se conectara la ESP32 (solo 2.4 GHz)
#define WIFI_SSID     "MiHotspot"
#define WIFI_PASSWORD "clave-segura-123"

// IP del equipo donde corre Docker (backend)
#define BACKEND_HOST  "192.168.137.1"   // Windows hotspot; Linux hotspot: "10.42.0.1"
#define BACKEND_PORT  8000
ConstanteQué poner
WIFI_SSIDNombre exacto de la red (distingue mayúsculas).
WIFI_PASSWORDContraseña de la red.
BACKEND_HOSTLa IP que encontraste arriba, entre comillas.
BACKEND_PORT8000, salvo que cambies el puerto en docker-compose.yml.
Verifica que no se suba

git status no debe listar config.h. Puedes confirmarlo con git check-ignore -v esp32/esp32_mensaje/config.h.
