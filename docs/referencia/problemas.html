Solución de problemas

Organizado por síntoma. Si no sabes por dónde empezar, sigue el diagrama.

Diagnóstico rápido

flowchart TD
    A{"¿Aparece el puerto COM / ttyUSB?"} -- No --> A1["Cable de datos, driver, dialout/brltty"]
    A -- Sí --> B{"¿Carga el firmware?"}
    B -- No --> B1["Botón BOOT, Upload Speed, placa correcta"]
    B -- Sí --> C{"¿Monitor Serie legible?"}
    C -- No --> C1["115200 baud"]
    C -- Sí --> D{"¿Dice 'Conectado'?"}
    D -- No --> D1["SSID/clave, 2.4 GHz, portal cautivo"]
    D -- Sí --> E{"¿'Nuevo mensaje' o 'Error HTTP'?"}
    E -- "Error HTTP -1" --> E1["BACKEND_HOST, Docker, firewall, misma subred"]
    E -- "Nuevo mensaje" --> F["✅ Todo funciona"]

Placa y carga

SíntomaCausa probableSolución
No aparece ningún puertoCable de solo carga o falta el driver.Prueba otro cable; instala CH340/CP210x (paso 5).
Linux: el puerto aparece y desaparecebrltty se apropia del CH340.sudo apt remove brltty
Linux: Permission denied: '/dev/ttyUSB0'Usuario fuera de dialout.sudo usermod -aG dialout $USER y volver a iniciar sesión.
Failed to connect to ESP32: No serial data received / se queda en Connecting....No entra en modo bootloader.Mantén BOOT al empezar la carga; baja Upload Speed a 115200.
A fatal error occurred: Could not open COMx, the port is busyOtro programa usa el puerto.Cierra otros Monitores Serie, PuTTY, Cura…
fatal error: config.h: No such file or directoryNo creaste config.h.Copia config.example.h → config.h (paso 6).
WiFi.h: No such file o no aparece “ESP32 Dev Module”Paquete de placas no instalado o placa equivocada.Instala esp32 by Espressif Systems y selecciona la placa ESP32.
Brownout detector was triggered en bucleAlimentación insuficiente al encender el WiFi.Otro cable/puerto USB, evitar hubs sin alimentación.

WiFi

SíntomaCausa probableSolución
Puntos infinitos .......SSID o clave incorrectos.Revisa mayúsculas, espacios y comillas en config.h.
Puntos infinitos con datos correctosRed de 5 GHz.Configura el hotspot/router en 2.4 GHz.
Conecta pero nunca llega al backend en la red de la universidadPortal cautivo o aislamiento de clientes.Usa el hotspot del computador.
WiFi desconectado, reconectando... frecuenteSeñal débil.Acerca la placa; no tapes la antena del módulo.

Red y backend

SíntomaCausa probableSolución
Error HTTP: -1No hay conexión TCP con BACKEND_HOST:8000.1) IP correcta (ipconfig/ip a); 2) misma subred que la ESP32; 3) docker compose ps; 4) firewall.
Error HTTP: -11Timeout: el host responde lento o filtra paquetes.Revisa firewall/antivirus.
Error HTTP: 404Otro servicio en ese puerto o ruta mal escrita.Abre la URL impresa por la ESP32 en el navegador.
La IP del PC cambió de un día a otroDHCP del router.Usa el hotspot (IP fija) o reserva la IP en el router.
Desde el celular no abre IP:3000Firewall o red distinta.Reglas de la sección de firewall.

Docker

SíntomaCausa probableSolución
error during connect … pipe/docker_engine (Windows)Docker Desktop cerrado.Ábrelo y espera Engine running.
permission denied … /var/run/docker.sock (Linux)Usuario fuera del grupo docker.sudo usermod -aG docker $USER y re-login.
Bind for 0.0.0.0:8000 failed: port is already allocatedOtro programa usa el 8000.Ciérralo o cambia el puerto (ver).
Docker Desktop: WSL 2 installation is incompleteWSL desactualizado.wsl --update y reiniciar.
Docker Desktop: Virtualization support not detectedVT-x/AMD-V desactivado.Actívalo en la BIOS/UEFI.
Cambié main.py y no se notaNo se reconstruyó la imagen.docker compose up -d --build

Frontend

SíntomaCausa probableSolución
“Error conectando al backend”Backend caído o puerto bloqueado.docker compose ps, docker compose logs backend.
Consola del navegador: blocked by CORS policySe quitó/restringió el middleware CORS.Revisa allow_origins en main.py.
Los cambios de CSS/JS no aparecenCaché del navegador.Ctrl+F5.
El mensaje volvió a “Hola mundo”Se reinició el backend (estado en memoria).Normal. Ver persistencia.
