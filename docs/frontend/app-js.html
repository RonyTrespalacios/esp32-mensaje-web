Lógica en app.js

35 líneas de JavaScript “vanilla” que leen el mensaje al cargar, lo refrescan cada 2 segundos y envían el nuevo valor al pulsar Guardar.

Código completo

// El backend corre en el mismo host que sirve el frontend, puerto 8000
const API = `http://${window.location.hostname}:8000`;

const actual = document.getElementById("actual");
const form = document.getElementById("form");
const input = document.getElementById("nuevo");
const estado = document.getElementById("estado");

async function cargarMensaje() {
  try {
    const res = await fetch(`${API}/mensaje`);
    const data = await res.json();
    actual.textContent = data.mensaje;
  } catch (e) {
    actual.textContent = "Error conectando al backend";
  }
}

form.addEventListener("submit", async (e) => {
  e.preventDefault();
  try {
    const res = await fetch(`${API}/mensaje`, {
      method: "PUT",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ mensaje: input.value }),
    });
    const data = await res.json();
    actual.textContent = data.mensaje;
    estado.textContent = "Mensaje actualizado ✔";
    input.value = "";
    setTimeout(() => (estado.textContent = ""), 2000);
  } catch (e) {
    estado.textContent = "Error al guardar";
  }
});

cargarMensaje();
setInterval(cargarMensaje, 2000); // refresco automático

La URL del backend

const API = `http://${window.location.hostname}:8000`;

window.location.hostname es el host con el que se abrió la página. Así la misma línea sirve en todos los casos sin editar nada:

Abres la web en…API vale…
http://localhost:3000http://localhost:8000
http://192.168.137.1:3000 (desde el celular)http://192.168.137.1:8000

Se usa una template string (comillas invertidas `…${…}`) para interpolar variables.

Referencias al DOM

document.getElementById obtiene una vez los elementos del HTML y se guardan en constantes para no buscarlos en cada actualización.

Leer el mensaje: cargarMensaje()

  • async / await: fetch devuelve una promesa (la respuesta llega en el futuro). await pausa la función hasta que llegue, sin bloquear la página.
  • fetch(url) hace un GET por defecto.
  • res.json() lee el cuerpo y lo convierte en objeto: {mensaje: "Hola mundo"}.
  • textContent (y no innerHTML) inserta el texto tal cual. Si alguien guarda <script>… como mensaje, se muestra como texto y no se ejecuta: protección básica contra XSS.
  • try/catch: si el backend está apagado, fetch lanza un error de red y se muestra “Error conectando al backend”.

Guardar: el evento submit

  1. e.preventDefault() evita el comportamiento por defecto del formulario (recargar la página enviando los datos por URL).
  2. fetch con method: "PUT", cabecera Content-Type: application/json y el cuerpo convertido a texto con JSON.stringify. Esta combinación es la que provoca la petición preflight de CORS (OPTIONS) que el backend autoriza.
  3. Actualiza la interfaz con el valor confirmado por el servidor, muestra “Mensaje actualizado ✔” y limpia el campo.
  4. setTimeout borra el aviso a los 2 s.

Refresco automático

cargarMensaje();
setInterval(cargarMensaje, 2000);

Primero carga inmediatamente y luego cada 2 s. Así, si otra persona (u otra pestaña, o un curl) cambia el mensaje, todas las páginas abiertas lo reflejan. Es el mismo patrón de polling que usa la ESP32.

Posibles mejoras

  • Comprobar res.ok antes de res.json() para mostrar errores 422/500 con claridad.
  • No sobrescribir el texto mientras el usuario está escribiendo (ya ocurre bien porque solo se toca #actual, no el input).
  • Pausar el setInterval cuando la pestaña está oculta (document.visibilityState).
  • Sustituir el polling por Server-Sent Events.
