Estructura HTML y CSS

El frontend son tres archivos estáticos, sin frameworks ni paso de compilación. nginx los entrega tal cual al navegador.

Cómo se sirve

flowchart LR
    B["Navegador"] -- "GET http://host:3000/" --> N["nginx (contenedor)"]
    N -- "lee" --> V["/usr/share/nginx/html<br/>= ./frontend del repo"]
    N -- "index.html, styles.css, app.js" --> B
    B -- "ejecuta app.js → fetch :8000" --> API["Backend"]

nginx no ejecuta nada del frontend: solo envía archivos. Toda la lógica corre en el navegador del usuario.

index.html

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Editor de mensaje</title>
  <link rel="stylesheet" href="styles.css">
</head>
<body>
  <main class="card">
    <h1>Mensaje para la ESP32</h1>
    <p class="label">Mensaje actual:</p>
    <p id="actual" class="actual">Cargando...</p>

    <form id="form">
      <input id="nuevo" type="text" placeholder="Escribe un nuevo mensaje" required>
      <button type="submit">Guardar</button>
    </form>
    <p id="estado" class="estado"></p>
  </main>
  <script src="app.js"></script>
</body>
</html>

Puntos clave

ElementoPropósito
<meta charset="UTF-8">Que tildes y emojis del mensaje se muestren bien.
<meta name="viewport">Que la página se adapte al ancho del celular en lugar de mostrarse “de escritorio” en miniatura.
id="actual"Párrafo donde app.js escribe el mensaje actual.
<form id="form">Usar un formulario permite enviar con Enter además del botón.
requiredEl navegador impide enviar el campo vacío sin escribir JavaScript.
id="estado"Mensajes de feedback (“Mensaje actualizado ✔” o error).
<script src="app.js"> al finalSe carga después de que existen los elementos, así getElementById los encuentra.

styles.css

Una hoja de estilos corta que centra una “tarjeta” blanca sobre fondo oscuro.

* { box-sizing: border-box; }
body {
  margin: 0;
  min-height: 100vh;
  display: flex;
  align-items: center;
  justify-content: center;
  font-family: system-ui, sans-serif;
  background: #1e293b;
  padding: 16px;
}
.card {
  background: #fff;
  padding: 2rem;
  border-radius: 12px;
  width: 100%;
  max-width: 480px;
  box-shadow: 0 10px 30px rgba(0,0,0,.3);
}
.actual { font-size: 1.5rem; font-weight: bold; word-break: break-word; }
form { display: flex; gap: .5rem; flex-wrap: wrap; }
input { flex: 1; min-width: 0; }
.estado { color: #16a34a; min-height: 1.2em; }

Técnicas usadas

  • box-sizing: border-box: el padding y el borde se incluyen en el ancho declarado; evita desbordes.
  • Flexbox en body (display:flex + align-items + justify-content) con min-height:100vh: centra la tarjeta vertical y horizontalmente.
  • width:100%; max-width:480px: ocupa todo el ancho en el celular, pero no más de 480 px en pantallas grandes.
  • Flexbox en el formulario con flex:1 en el input: el campo crece y el botón mantiene su tamaño; flex-wrap permite que bajen de línea en pantallas muy estrechas.
  • word-break: break-word: un mensaje largo sin espacios no rompe el diseño.
  • min-height: 1.2em en .estado: reserva el espacio para que la tarjeta no “salte” cuando aparece el texto de confirmación.
Experimenta

Como frontend/ está montado como volumen, puedes cambiar colores en styles.css, guardar y pulsar Ctrl+F5 en el navegador para verlo al instante.
