GET /mensaje

Devuelve el mensaje actual envuelto en un objeto JSON.

Respuesta 200

HTTP/1.1 200 OK
content-type: application/json

{"mensaje":"Hola mundo"}

Ejemplos

Invoke-RestMethod http://localhost:8000/mensaje
curl http://localhost:8000/mensaje

GET /mensaje/texto

Devuelve solo el texto, sin comillas ni JSON. Pensado para microcontroladores.

Respuesta 200

HTTP/1.1 200 OK
content-type: text/plain; charset=utf-8

Hola mundo

Ejemplos

(Invoke-WebRequest http://localhost:8000/mensaje/texto).Content
curl http://localhost:8000/mensaje/texto

En la ESP32:

HTTPClient http;
http.begin("http://192.168.137.1:8000/mensaje/texto");
if (http.GET() == 200) {
  String m = http.getString();   // "Hola mundo"
}
http.end();

PUT /mensaje

Reemplaza el mensaje por el enviado. Operación idempotente.

Cuerpo de la petición

CampoTipoObligatorioDescripción
mensajestringSíNuevo texto.
 
PUT /mensaje HTTP/1.1
Content-Type: application/json

{"mensaje":"Encender LED"}

Respuesta 200

{"mensaje":"Encender LED"}

Respuesta 422 (validación)

Si falta el campo o no es un texto:

{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "mensaje"],
      "msg": "Field required",
      "input": {}
    }
  ]
}

Ejemplos

Invoke-RestMethod -Method Put -Uri http://localhost:8000/mensaje `
  -ContentType "application/json" -Body '{"mensaje":"Encender LED"}'
curl -X PUT http://localhost:8000/mensaje \
  -H "Content-Type: application/json" \
  -d '{"mensaje":"Encender LED"}'

Desde JavaScript (así lo hace el frontend):

await fetch("http://localhost:8000/mensaje", {
  method: "PUT",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ mensaje: "Encender LED" }),
});

Códigos de estado

CódigoCuándo
200 OKPetición correcta.
404 Not FoundRuta inexistente (p. ej. /mensajes).
405 Method Not AllowedMétodo no soportado en la ruta (p. ej. POST /mensaje o PUT /mensaje/texto).
422 Unprocessable EntityCuerpo del PUT inválido.
-1 (en la ESP32)No es HTTP: HTTPClient no pudo conectar (IP/puerto/firewall).
