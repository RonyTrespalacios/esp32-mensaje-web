Docker y docker compose

Docker empaqueta el backend con su intérprete de Python y dependencias en una imagen; Compose arranca backend y frontend juntos con la configuración de puertos y volúmenes.

Dockerfile del backend

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY main.py .
EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
InstrucciónQué hace
FROM python:3.12-slimParte de una imagen oficial de Debian mínima con Python 3.12 (~50 MB comprimida).
WORKDIR /appCrea y se sitúa en /app dentro de la imagen.
COPY requirements.txt .Copia solo la lista de dependencias…
RUN pip install ……e instala. Al ir antes de copiar el código, Docker reutiliza esta capa en caché si solo cambias main.py: las reconstrucciones tardan segundos.
COPY main.py .Copia el código de la aplicación.
EXPOSE 8000Documenta el puerto que usa el contenedor (no lo publica por sí mismo).
CMD [...]Comando al arrancar: uvicorn sirviendo main:app. --host 0.0.0.0 es imprescindible: con 127.0.0.1 solo aceptaría conexiones desde dentro del propio contenedor.

docker-compose.yml

services:
  backend:
    build: ./backend
    container_name: mensaje-backend
    ports:
      - "8000:8000"
    restart: unless-stopped

  frontend:
    image: nginx:alpine
    container_name: mensaje-frontend
    ports:
      - "3000:80"
    volumes:
      - ./frontend:/usr/share/nginx/html:ro
    depends_on:
      - backend
    restart: unless-stopped

Servicio backend

  • build: ./backend: construye la imagen con el Dockerfile de esa carpeta.
  • container_name: nombre fijo para identificarlo en docker ps y en los logs.
  • ports: "8000:8000": formato HOST:CONTENEDOR. Lo que llegue al puerto 8000 del computador (por cualquier interfaz) se reenvía al 8000 del contenedor.
  • restart: unless-stopped: si el proceso falla o reinicias el PC/Docker, vuelve a arrancar solo, salvo que lo hayas parado a mano.

Servicio frontend

  • image: nginx:alpine: imagen oficial de nginx sobre Alpine Linux (~20 MB). No hay que construir nada.
  • ports: "3000:80": nginx escucha en el 80 dentro del contenedor; fuera lo vemos en el 3000.
  • volumes: ./frontend:/usr/share/nginx/html:ro: monta la carpeta frontend en la carpeta que nginx sirve por defecto, en solo lectura (:ro). Por eso los cambios en HTML/JS se ven al recargar, sin reconstruir.
  • depends_on: backend: arranca el backend primero (no espera a que esté “listo”, solo a que se haya iniciado).

Compose crea una red privada donde los servicios se encuentran por nombre (http://backend:8000). En este proyecto no se usa porque el JavaScript del frontend se ejecuta en el navegador (fuera de Docker), que no conoce ese nombre; por eso app.js usa la IP/host del computador.

Comandos útiles

ComandoEfecto
docker compose up -d --buildConstruir y arrancar en segundo plano.
docker compose psEstado y puertos.
docker compose logs -f backendLogs en vivo del backend.
docker compose exec backend shAbrir una shell dentro del contenedor.
docker compose restart backendReiniciar un servicio.
docker compose downParar y borrar contenedores y red.
docker image pruneLiberar espacio de imágenes antiguas.
¿El puerto 8000 está ocupado?

Cambia solo el lado del host: "8080:8000". Después actualiza BACKEND_PORT en config.h y la constante API en frontend/app.js. Ver Todo lo configurable.
