Firmware (esp32_mensaje.ino)

El sketch se conecta al WiFi, consulta el backend cada segundo y solo imprime cuando el mensaje cambia.

config.example.h

#pragma once

// Red WiFi a la que se conectara la ESP32 (solo 2.4 GHz)
#define WIFI_SSID     "NOMBRE_DE_TU_RED"
#define WIFI_PASSWORD "CLAVE_DE_TU_RED"

// IP del equipo donde corre Docker (backend). Ver README > "Que cambiar"
// Ejemplo hotspot de Windows: 192.168.137.1
#define BACKEND_HOST  "192.168.137.1"
#define BACKEND_PORT  8000
  • #pragma once: evita que el archivo se incluya dos veces.
  • #define: macros del preprocesador. Antes de compilar, cada aparición de WIFI_SSID se sustituye literalmente por "NOMBRE_DE_TU_RED".
  • BACKEND_PORT es un número (sin comillas) y BACKEND_HOST un texto (con comillas).

Código completo

#include <WiFi.h>
#include <HTTPClient.h>

// Credenciales WiFi e IP del backend (NO se sube a GitHub).
// Si no existe, copia "config.example.h" como "config.h" y editalo.
#include "config.h"

const char* ssid     = WIFI_SSID;
const char* password = WIFI_PASSWORD;

// Endpoint de texto plano del backend
String url = String("http://") + BACKEND_HOST + ":" + BACKEND_PORT + "/mensaje/texto";

String ultimoMensaje = "";

void setup() {
  Serial.begin(115200);
  WiFi.begin(ssid, password);
  Serial.print("Conectando a WiFi");
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println();
  Serial.print("Conectado. IP ESP32: ");
  Serial.println(WiFi.localIP());
  Serial.print("Consultando: ");
  Serial.println(url);
}

void loop() {
  if (WiFi.status() == WL_CONNECTED) {
    HTTPClient http;
    http.begin(url);
    int code = http.GET();
    if (code == 200) {
      String mensaje = http.getString();
      if (mensaje != ultimoMensaje) {
        Serial.print("Nuevo mensaje: ");
        Serial.println(mensaje);
        ultimoMensaje = mensaje;
      }
    } else {
      Serial.printf("Error HTTP: %d\n", code);
    }
    http.end();
  } else {
    Serial.println("WiFi desconectado, reconectando...");
    WiFi.reconnect();
  }
  delay(1000);
}

Explicación

Includes

  • <WiFi.h>: control del WiFi del ESP32 (objeto global WiFi).
  • <HTTPClient.h>: cliente HTTP de alto nivel sobre TCP.
  • "config.h": con comillas, se busca primero en la carpeta del sketch. Si no existe, la compilación falla con config.h: No such file or directory.

Variables globales

String url = String("http://") + BACKEND_HOST + ":" + BACKEND_PORT + "/mensaje/texto";
String ultimoMensaje = "";

La URL se arma una vez al arrancar concatenando objetos String de Arduino (que aceptan sumar números). Con los valores de ejemplo resulta http://192.168.137.1:8000/mensaje/texto. ultimoMensaje recuerda el último valor impreso.

setup(): una sola vez al arrancar

  1. Serial.begin(115200): abre UART0 a 115200 baudios. El Monitor Serie debe usar la misma velocidad.
  2. WiFi.begin(ssid, password): inicia la conexión en modo estación. Es asíncrono: retorna de inmediato.
  3. Bucle while: comprueba WiFi.status() cada 500 ms imprimiendo un punto, hasta obtener WL_CONNECTED (asociado a la red y con IP por DHCP). Si las credenciales son incorrectas, se queda aquí para siempre.
  4. Imprime la IP asignada (WiFi.localIP()) y la URL que va a consultar: datos clave para depurar.

loop(): se repite indefinidamente

  1. ¿Sigue conectado? Si no, imprime un aviso y llama a WiFi.reconnect().
  2. HTTPClient http; http.begin(url); prepara la petición (aún no se conecta).
  3. http.GET() abre TCP, envía GET /mensaje/texto HTTP/1.1 y espera la respuesta. Devuelve el código HTTP (200, 404…) o un número negativo si falló la conexión (-1 = connection refused / host inalcanzable; -11 = timeout).
  4. Si es 200, http.getString() lee el cuerpo. Solo si difiere de ultimoMensaje lo imprime y lo guarda; así el Monitor no se llena con la misma línea cada segundo.
  5. http.end() cierra la conexión y libera memoria. Imprescindible.
  6. delay(1000) espera 1 s antes de la siguiente consulta.

Detalles y buenas prácticas

  • delay() bloquea: durante ese segundo la ESP32 no hace nada más. Si añades botones o sensores, usa millis() para temporizar sin bloquear (ver guía).
  • String y memoria: concatenar String repetidamente fragmenta el heap. Aquí es aceptable porque los textos son cortos y se liberan en cada vuelta.
  • Mensajes con tildes: viajan en UTF-8 y el Monitor Serie de Arduino IDE 2 los muestra bien.
  • Sin timeout explícito: si el servidor no responde, GET() espera el timeout por defecto (~5 s). Se puede ajustar con http.setTimeout(2000).
