Vista física vs. vista lógica

Un mismo sistema se puede describir por cómo está cableado (física) o por cómo fluye la información entre programas (lógica). Confundirlas es la causa de la mayoría de errores de red.

Figura 1. El cable USB cumple tres funciones: alimentar, programar y transportar el Monitor Serie. Los datos de la aplicación viajan por radio, no por el cable.

Capas de red (modelo TCP/IP)

Una petición de la ESP32 atraviesa estas capas; cada una resuelve un problema distinto:

CapaEn la ESP32En el computador
AplicaciónHTTPClient: GET /mensaje/textoFastAPI / uvicorn
TransporteTCP, puerto origen efímero → destino 8000Docker reenvía :8000 al contenedor
RedIPv4 192.168.137.x → 192.168.137.1Pila IP de Windows/Linux
Enlace / físicoWiFi 802.11 b/g/n, 2.4 GHzAdaptador WiFi en modo AP o cliente
Para diagnosticar, recorre las capas de abajo hacia arriba
  1. ¿Hay enlace? → el Monitor Serie dice Conectado.
  2. ¿Hay IP en la misma subred? → compara la IP de la ESP32 con BACKEND_HOST.
  3. ¿El puerto TCP está abierto? → abre http://BACKEND_HOST:8000/mensaje desde el celular.
  4. ¿La aplicación responde bien? → docker compose logs backend.
